# Step2 · 03 变量版本化与前缀重命名（核心卡点）

> TEACH 第 3 步：微观串行——只解决「版本栈怎么压、怎么弹」这一个卡点。

## 先抛一个猜测（猜测试错）

> 你是不是以为：「从头到尾遍历指令，每遇到一次写入就把版本号 +1，读取时就取当前的版本」？

**只对了一半。** 这样的「线性计数」在**有分支**时会错：

```text
        if (c) { x = 1; } else { x = 2; }   // 两个分支都写 x
        use(x);                              // 这里读哪一版？
```

- 两条分支各自加一次版本号 → 版本号可能重复或跳号；
- 更关键：到达 `use(x)` 的路径不同，合法版本也不同，**线性计数无法表达「按路径取值」**。

正解是：**沿支配树做深度优先遍历，并为每个槽维护一个「版本栈」**。

---

## 卡点 ⚠️2：版本栈的压入 / 弹回

### 核心规则（背下来）

```text
进入一个块：
  (a) 压入该块所有 phi 定义的版本；           ← 汇合点的「新值」
  (b) 顺序处理块内指令：先记录 use，再压入 def；
离开一个块：
  (c) 弹回本块压入的**全部**版本；            ← 恢复「父块视角」
```

为什么这样对？因为支配树 DFS 有一个性质：

> **栈顶，永远是「此刻支配当前块的那个版本」。**

- 父块支配子块 → DFS 先访问父块，父块压入的版本在子块可见（栈里还在）；
- 兄弟块之间互不支配 → 访问完第一个兄弟后，它的版本被弹掉，不会污染第二个兄弟。

### 图解

```text
        B0 (x=v0)          进入B0: push v0          栈: [v0]
       /   \
     B1     B2            进入B1: push v1          栈: [v1, v0]
     |       |             离开B1: pop v1           栈: [v0]
     |       |             进入B2: push v2          栈: [v2, v0]
     \       /             离开B2: pop v2           栈: [v0]
        B3 (phi)          进入B3: push v3(phi)     栈: [v3, v0]
```

每次 load 读到的就是「**当前栈顶**」，天然正确。

## iinc 的微妙之处（本项目特意处理）

`iinc`（自增）**既是 use 又是 def**：

```text
slot2 += 1   ; 先读 slot2 的当前值，再写回一个新版本
```

本项目在 `Renamer.enterBlock` 里把「先 use、后 def」写死在指令处理顺序上：

```java
int us = useSlot(insn);
if (us >= 0) uses.computeIfAbsent(i, k -> new ArrayList<>())
        .add(new SsaVariable(us, stacks.get(us).peek()));   // 先读
int ds = defSlot(insn);
if (ds >= 0) {
    int v = versionCounter[ds]++;
    stacks.get(ds).push(v);                                  // 后写
    pushedLog.add(ds);
    definitions.put(i, new SsaVariable(ds, v));
}
```

> ⚠️ **易误判**：如果先 def 后 use，`iinc` 会读到「刚写入的新版本」，语义就错了。

## 用「显式栈」代替递归（工程细节）

递归 DFS 在深控制流上可能爆栈。本项目用**显式帧栈**模拟递归，帧里记住「离开时要弹到哪个位置」：

```java
// 帧 = {块id, 下一个子节点下标, 进入时的推送水位}
Deque<int[]> frames = new ArrayDeque<>();
int mark = pushedLog.size();
enterBlock(0);
frames.push(new int[]{0, 0, mark});
while (!frames.isEmpty()) {
    int[] frame = frames.peek();
    ...
    if (frame[1] < children.size()) {        // 还有子节点
        int child = children.get(frame[1]++);
        int childMark = pushedLog.size();
        enterBlock(child);                    // 进入：压版本
        frames.push(new int[]{child, 0, childMark});
    } else {                                  // 子节点都访问完
        while (pushedLog.size() > frame[2])   // 离开：弹回水位
            stacks.get(pushedLog.remove(pushedLog.size()-1)).pop();
        frames.pop();
    }
}
```

`pushedLog` 记录「压过哪些槽」，保证弹回**精确到位**——这正是卡点 ⚠️2 的落地。

## 与 phi 操作数填充的联动

离开一个块之前，要用**当前版本栈**去填后继块 phi 的操作数（卡点 ⚠️3）：

```java
for (int t : succs) {
    for (PhiNode phi : blockPhis.get(t)) {
        SsaVariable operand = new SsaVariable(phi.slot(), stacks.get(phi.slot()).peek());
        for (int idx = 0; idx < preds.get(t).size(); idx++)
            if (preds.get(t).get(idx) == blockId) phi.setOperand(idx, operand);
    }
}
```

至此，三阶段（定值收集 → phi 放置 → 前缀重命名）闭环。
