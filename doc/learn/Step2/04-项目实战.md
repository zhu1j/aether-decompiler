## 阶段 0：确定槽位上界

```java
int slotCount = Math.max(0, method.maxLocals());
for (Insn insn : insns) {
    int s = Math.max(useSlot(insn), defSlot(insn));
    if (s >= slotCount) slotCount = s + 1;      // 容忍比 maxLocals 更大的槽（防御）
}
```

> 为什么防御？某些被篡改/生成的字节码里，指令引用的槽号可能超过 `maxLocals`。
> 宁可多开一点数组，也不要越界崩溃——这是「生产级」与「玩具」的分野之一。

## 操作数解析：字节码里的「槽号」怎么读

本项目没有反汇编器，`Insn.operand()` 是人可读字符串。于是 `SsaBuilder` 自带两个小解析器：

```java
static int useSlot(Insn insn) {
    int op = insn.opcode();
    if (op >= 21 && op <= 25) return parseVar(insn.operand());   // iload..aload
    if (op >= 26 && op <= 45) return (op - 26) % 4;              // iload_0..3 家族
    if (op == 132 || op == 169) return parseVar(insn.operand()); // iinc / ret
    return -1;
}
```

> **工程洞察**：紧凑形式的 `iload_0..3`（0x1A..0x2D）**隐含**槽号，必须用
> `(op - 26) % 4` 反推；通用形式的 `iload`（0x15）才需要解析操作数 `"var N"`。
> 这是字节码知识 → 代码的直接映射（呼应 Step1「字节码基础」）。

## 产出：SsaForm 提供什么

```java
ssa.phis()             // 全部 phi 节点
ssa.definitionAt(idx)  // 第 idx 条指令定义了哪个 SSA 值
ssa.usesAt(idx)        // 第 idx 条指令读取了哪些 SSA 值
ssa.phisInBlock(b)     // 某块上的 phi
```

这三样就是「定值-使用链」的全部原材料。

## 一次完整的手工推演（建议自己走一遍）

以 `sumTo`（循环求和）为例：

1. 入口块 B0 写 `sum` → `v1_0`? 不，参数先占 `v1_0`，`sum=0` 是 `v1_1`；
2. 循环头 B_h 有两条前驱（来自 B0 和回边）→ `sum` 与 `i` 都需要 phi；
3. phi 的操作数：从 B0 来取 `v1_1`，从回边来取循环内定值版；
4. 循环退出后读 sum → 栈顶即 phi 定义的版本。

> 想核对自己的推演？运行 `SsaBuilderTest#loopMethodHasPhisAndSingleAssignment`，
> 或在 GUI「分析」页签打开任一含循环的类，直接看 phi 列表。
