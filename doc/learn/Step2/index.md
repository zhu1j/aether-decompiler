## 模块速查表

| 模块 | 一句话总结 | 现实场景（我在哪用到） | 关联卡点 |
|------|-----------|----------------------|---------|
| SSA 本质 | 给每次赋值发新名字，让值的来源唯一 | 反编译器还原变量 / 污点分析 | 变量可被覆盖 |
| 支配关系 | idom + 支配树 = 「谁管得到谁」 | CFG 分析地基（Phase1） | 迭代求 idom |
| 支配边界 | 影响力失效处 = 必须汇合处 = phi 的家 | 决定 phi 插在哪 | ⚠️DF 定义易记混 |
| phi 节点 | 按「从哪条边来」取对应操作数 | 循环/分支汇合 | ⚠️操作数须按边对齐 |
| 版本化与重命名 | 版本栈 + 支配树 DFS，栈顶即到达定值 | 每次改写 load 指向 | ⚠️进压出弹、iinc 先读后写 |
| 定值-使用链 | definitions / uses 两张表 | 常量传播/活跃性 | — |

## 核心不变量（背下来）

```text
1) 每条 SSA 值只被定义一次。
2) phi 的操作数数量 == 该块前驱数量（含异常边）。
3) 任一使用点读取的版本 == 支配树 DFS 到此处的「栈顶」。
```

## 算法速记

```text
阶段1  收集每个槽的定值块
阶段2  for 每个定值块: 沿支配边界迭代上溯 → 插 phi
阶段3  沿支配树 DFS：
         进块: push 本块 phi 版本 → 逐指令「先use后def」
         出块: pop 回水位
         填 phi: 用栈顶按前驱下标对齐
```

## 一句话记忆钩子

- **SSA** = 给每次赋值发新名字。
- **支配边界** = phi 的家。
- **版本栈** = 「栈顶即到达定值」。
- **异常边** = 别忘的前驱。
