## 一句话本质

> **AST = 把「一堆跳转指令」翻译成「一棵有层次的语句树」，让人和程序都能一眼看懂结构。**

它是反编译/编译的中心枢纽：前端把线性代码变成树，后端把树变成目标代码。对本项目而言，
AST 是 Phase3 的产物，也是「不依赖第三方反编译器就能输出可读源码」的关键一步。

---

## 俯瞰框架（先看全貌）

```text
AST 知识体系
├── A. 为什么需要 AST（从指令到结构）
│   ├── 字节码是「线性 + 跳转」；人脑读的是「嵌套」
│   └── AST = 语言中立的语法骨架（不含关键字）
├── B. 表达式重建（栈模拟）
│   ├── 操作数栈 ↔ 表达式树
│   └── load→取值 / 运算→Binary / invokestatic→Call        ⚠️卡点
├── C. 语句与语句树
│   ├── ExprStmt / Return / Throw / Block
│   └── If / While / DoWhile / Switch / TryCatch
├── D. 控制结构恢复（structuring）
│   ├── 自然循环识别（回边 + 支配）                          ⚠️核心卡点
│   ├── if-else 的「汇合点」求解                              ⚠️核心卡点
│   └── 不可规约控制流的诚实降级（标签 + goto）              ⚠️易误判
└── E. 产出：MethodBody + 源码映射锚点（firstInsn/lastInsn）
```

对照本项目文件：

```text
com.aetherdecompiler.core.ast
├── AstNode            → 公共基类（携带指令区间，供映射用）
├── Expr               → 表达式：Const/Local/Binary/Call/...
├── Stmt               → 语句：Block/If/While/Return/TryCatch/...
├── ExpressionBuilder  → 栈模拟重建（B 层）
├── ControlStructurer  → 控制结构恢复（D 层）
├── MethodBody         → 产出容器（E 层）
├── AstBuilder         → 编排器
└── JavaAstRenderer    → 渲染成 Java + 同步出映射（Phase4 联动）
```

## 关键卡点

| # | 卡点 | 为什么难 / 易误判 |
|---|------|------------------|
| ⚠️1 | **栈模拟的「弹两压一」** | 运算指令弹几个、压几个必须精确；错一个，整个表达式树就歪了 |
| ⚠️2 | **自然循环识别** | 「回边」= 后继能支配前驱的边；只有识别对回边，才知谁循环头 |
| ⚠️3 | **if-else 的汇合点** | 两个分支可能各自再嵌套分支，「它们从哪合流」要能算出来 |
| ⚠️4 | **不可规约控制流的降级** | goto 乱跳无法结构化时，要**诚实保留标签**，而不是伪造错误结构 |

> 本项目对 ⚠️4 的态度是刻意的：宁可输出带标签的近似，也不输出看似漂亮却错误的树。
