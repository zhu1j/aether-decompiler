# Step4 · SourceMapping 源码映射（成体系学习地图）

> 目标：把「生成文本 ↔ 字节码」双向定位这块知识建框讲清，并对应本仓库实现。
>
> 作者：Jerry Zhu (Zeek) ｜ 座右铭：*Run the Code, Run the World!*

## 一句话本质

> **SourceMapping = 一张对照表，让「我看到的这行代码」与「真正执行的那条字节码」互相指认。**

## 为什么需要它

反编译器的输出若不能**回到字节码**，就只是「看起来像源码的文本」。调试、审计、教学中
真正有用的是**双向可追溯**：

```text
点击源码第 12 行  →  高亮对应字节码 4 条指令
选中字节码第 27 条  →  高亮它生成的那段源码
```

## 俯瞰框架

```text
SourceMapping 知识体系
├── A. Span：一段映射的基本单位
│   ├── 生成侧：开始/结束 行·列
│   ├── 目标侧：开始/结束 指令索引
│   └── 溯源侧：原始源码行（若有）
├── B. 锚点从哪来（AST 的基因）
│   └── 每个 AST 节点天生带 firstInsn/lastInsn          ⚠️关键
├── C. 建立时机：边渲染边记录
│   └── 渲染器每写一行 → 同步 add 一个 span
└── D. 双向查询
    ├── atGenerated(line,col) → Span（接口承诺）
    └── atInsn(insnIndex) → List<Span>（能力增强）      ⚠️反向
```

## 关键卡点

| # | 卡点 | 为什么难 / 易误判 |
|---|------|------------------|
| ⚠️1 | **锚点不是事后补的** | 若渲染完再想映射，就得重新解析文本；正解是渲染时同步记录 |
| ⚠️2 | **区间是「半开」还是「闭」** | 容易差一，导致边界行错位 |
| ⚠️3 | **反向查询接口未承诺** | 接口只给正向 `atGenerated`，反向要自己加 |
