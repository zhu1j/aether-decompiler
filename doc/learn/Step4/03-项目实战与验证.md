# Step4 · 03 项目实战与验证

> 把 SourceMapping 的知识，与本项目的实现对应起来，并用测试确认。

## 端到端链路

```text
字节码
  │ AsmClassParser
  ▼
ClassModel
  │ CfgBuilder + DominatorTree
  ▼
CFG + 支配树
  │ AstBuilder（ControlStructurer + ExpressionBuilder）
  ▼
MethodBody（AST，节点带 firstInsn/lastInsn）
  │ JavaAstRenderer（边渲染边登记 Span）
  ▼
SourceTree { path, content, mapping }
```

关键点：**映射不是独立模块**，而是 AST 渲染的产物。这条链路也解释了为什么 AST 节点
必须携带指令区间（Step3 提到的「基因」）。

## 核心类职责

| 类 | 职责 |
|----|------|
| `SourceMapping`（api） | 接口：`spans()` + `atGenerated(line,col)` |
| `SourceMapping.Span`（api） | 一条映射（生成三侧坐标 + 指令区间） |
| `DefaultSourceMapping`（core） | 实现 + 反向查询 `atInsn(idx)` + Builder |
| `JavaAstRenderer` | 渲染时同步产出映射 |
| `SourceTree`（api） | 渲染输出单元：`path + content + mapping` |

## Builder 用法

```java
DefaultSourceMapping m = DefaultSourceMapping.builder()
        .add(genStartLine, genStartCol, genEndLine, genEndCol, insnStart, insnEnd, sourceLine)
        .add(...)                 // 链式追加
        .build();                 // 冻结为不可变
```

## 验证单测

`aether-core/src/test/java/com/aetherdecompiler/core/AstBuilderTest.java`：

```java
MethodBody body = bodyFor(sample(), "sumTo", "(I)I");
SourceTree tree = new JavaAstRenderer().render(body);   // 渲染即产映射
assertTrue(tree.content().contains("class Sample"));
assertNotNull(tree.mapping());
assertTrue(tree.mapping().spans().size() > 0);
SourceMapping.Span first = tree.mapping().spans().get(0);
assertNotNull(tree.mapping().atGenerated(first.generatedStartLine(),
                                         first.generatedStartCol()));   // 正向可反查
```

## 自测题

1. 为什么 `insnEnd` 用「不含尾」，而 `lastInsn + 1`？
2. 装饰性的缩进行没有指令来源，映射里怎么表示？
3. 反向查询为什么接口没承诺？加了它会破坏契约吗？
4. 若两个 span 的生成起点相同，`byStart` 用 `putIfAbsent` 表示什么取舍？

<details>
<summary>参考答案</summary>

1. 统一「半开区间」，避免边界差一；查询 `idx < end` 与之一致。
2. 用 `-1` 表示「无指令来源」。
3. 接口只承诺最小能力；`DefaultSourceMapping` 额外提供 `atInsn` 是增强，不破坏既有契约。
4. 保留「最先登记者」，保证查询稳定、可预测，不因后加者而抖动。

</details>

## 一句话收尾

```text
AST 带锚点 → 渲染时登记 → 双向可查。映射与渲染同源，永不错位。
```
