# Step5 · 流水线 / 缓存 / 并行（成体系学习地图）

> 目标：把「把各阶段串成一条生产级流水线」这块工程知识建框讲清，并对应本仓库实现。
>
> 作者：Jerry Zhu (Zeek) ｜ 座右铭：*Run the Code, Run the World!*

## 一句话本质

> **流水线 = 把「模型 → CFG → SSA → AST」各阶段串起来，并让每个中间产物只算一次、
> 多个类并行算。**

## 俯瞰框架

```text
流水线知识体系
├── A. 为什么需要流水线
│   ├── 阶段之间有依赖（AST 需要 CFG+支配树）
│   └── 重复计算昂贵 → 需要缓存
├── B. 缓存（同一产物只算一次）
│   ├── 键 = 类内部名 + 方法标识
│   ├── 值 = 不可变快照 MethodAnalysis            ⚠️可共享
│   └── ConcurrentHashMap + putIfAbsent            ⚠️并发安全
├── C. 并行（类与类独立）
│   ├── 调用方注入 ExecutorService
│   └── 内核不持有线程池（有意的克制）            ⚠️设计决策
└── D. 事件（进度可见）
    └── 每个阶段完成发布 AetherEvent
```

## 关键卡点

| # | 卡点 | 为什么难 / 易误判 |
|---|------|------------------|
| ⚠️1 | **哪些能缓存、哪些不能** | 缓存的可变对象会跨线程出问题；本项目靠「一切产物不可变」化解 |
| ⚠️2 | **putIfAbsent 而非 put** | 并发下两个线程可能同时算同一方法，需保证只留一份 |
| ⚠️3 | **线程池该不该由内核创建** | 内核持有线程池会与宿主（GUI）策略冲突；应「注入」而非「拥有」 |
| ⚠️4 | **失败要能传递** | 并行子任务的异常不能吞，需经 Future.get() 抛出 |
