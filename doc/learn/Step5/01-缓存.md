# Step5 · 01 缓存（同一产物只算一次）

> TEACH 第 3 步：微观串行——只解决「缓存什么、怎么安全地缓存」这一个卡点。

## 先抛一个猜测（猜测试错）

> 你是不是以为：「直接把中间结果放进一个 Map 就行」？

**在单线程里对；在并行下危险。** 关键在于：**被缓存的必须是不可变的**。
否则两个线程共享同一个可变对象，一个在读、一个在改，就会出问题。

## 卡点 ⚠️1：哪些能缓存 —— 不可变是前提

本项目的每一层产物都是**不可变快照**（这是贯穿全项目的设计红线）：

```text
ClassModel / ControlFlowGraph / DominatorTree / SsaForm / MethodBody
   —— 全部「构造时冻结、之后只读」
```

因此，把 `MethodAnalysis`（一个 record，天然不可变）缓存起来并跨线程共享是安全的：

```java
public record MethodAnalysis(ClassModel owner, MethodModel method,
                             ControlFlowGraph cfg, DominatorTree dom,
                             SsaForm ssa, MethodBody ast) { }
```

> **工程洞察**：不可变性不是「洁癖」，而是**让并发变简单的杠杆**。一旦对象不可变，
> 缓存、共享、并行都无需加锁，只需保证「只写一次」。

## 缓存键与值

```java
private final Map<String, MethodAnalysis> cache = new ConcurrentHashMap<>();

public MethodAnalysis analyzeMethod(ClassModel owner, MethodModel method) {
    String key = owner.name() + "#" + method.id();     // 类内部名 + 方法标识
    MethodAnalysis hit = cache.get(key);
    if (hit != null) return hit;                       // 命中：直接返回
    ... 计算 cfg/dom/ssa/ast ...
    MethodAnalysis prior = cache.putIfAbsent(key, analysis);
    return prior != null ? prior : analysis;           // ⚠️ putIfAbsent，不是 put
}
```

## 卡点 ⚠️2：`putIfAbsent` 而非 `put`

并发下，两个线程可能**同时**发现缓存未命中、同时计算同一方法。若用 `put`，后者会覆盖
前者的结果——虽然结果等价，但会**破坏「同一 key 返回同一实例」的引用一致性**，进而可能
让 `==` 判断或 identity 缓存失效。

`putIfAbsent` 保证：**首次写入者获胜，其余线程复用它**。

```java
MethodAnalysis prior = cache.putIfAbsent(key, analysis);
return prior != null ? prior : analysis;   // 有别人先放了 → 用别人的
```

> 单测 `DecompilationPipelineTest.cacheReturnsSameInstanceForRepeatedRequest` 用
> `assertSame(first, second)` 直接验证这条不变量。

## 缓存粒度

| 层级 | 是否缓存 | 说明 |
|------|---------|------|
| ClassModel | 由来源层缓存 | 解析一次 |
| CFG / 支配树 | 随方法分析缓存 | 复用 |
| SSA | 随方法分析缓存（可关） | `withSsa(false)` 可跳过 |
| AST | 随方法分析缓存 | 复用 |

## 一句话记住

```text
不可变 ⇒ 可缓存可共享。键 = 类#方法。写入用 putIfAbsent，保证同键同实例。
```
