# Step5 · 03 项目实战与验证

## 端到端：一个类走完流水线

```java
DecompilationPipeline pipe = new DecompilationPipeline().withEventBus(bus);
ClassAnalysis ca = pipe.analyze(classModel);          // Model→CFG→Dom→SSA→AST
for (MethodAnalysis m : ca.methods()) {
    m.ssa().phiCount();                               // SSA 成果
    new JavaAstRenderer().render(m.ast());            // AST + 映射
}
```

## 多类并行

```java
JarClassSource src = ...;                              // 类来源
try (ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
    List<ClassAnalysis> all = pipe.analyzeAll(src, pool);   // 类级并行
}
```

> 也可调用 `analyzeAll(src)`（便捷入口，内部自建池并关闭）。

## 核心成员速查

| 成员 | 作用 |
|------|------|
| `analyze(ClassModel)` | 单类全流水线 |
| `analyzeMethod(owner, method)` | 单方法 + 缓存 |
| `analyzeAll(src, executor)` | 多类并行（注入池） |
| `analyzeAll(src)` | 多类并行（自建池） |
| `withEventBus(bus)` | 绑定事件总线 |
| `withSsa(bool)` | 开关 SSA 阶段 |
| `cachedMethodCount()` / `clearCache()` | 缓存观测 / 清理 |

var pipeline = new DecompilationPipeline();

## 自测题

1. 为什么缓存的对象必须不可变？如果缓存了可变对象会发生什么？
2. `put` 与 `putIfAbsent` 在并发缓存里有何本质差别？
3. 为什么内核不自己 new 一个线程池？
4. 并行收集结果时，为什么用 `Future` 列表而不是 `parallelStream` 的 `collect`？
5. 事件总线为空（未绑定）时会发生什么？

<details>
<summary>参考答案</summary>

1. 可变对象被多线程共享会出现数据竞争（读写交错）；不可变对象只读共享安全。
2. `put` 会覆盖，破坏「同键同实例」；`putIfAbsent` 只让首次写入生效。
3. 内核拥有线程池会与宿主线程模型冲突，且生命周期/数量不可控；应注入。
4. `parallelStream` 不保证顺序与异常语义清晰；`Future` 列表可精确按输入序收集并穿透异常。
5. `publish` 直接跳过（`bus == null`），引擎照常运行，只是不发布事件。

</details>
